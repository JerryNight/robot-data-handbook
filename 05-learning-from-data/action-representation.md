# 动作表示：一个看起来属于模型、实际属于数据格式的决定

> 阶段 5 · 从数据学策略 ｜ 写作时间 2026-11
>
> 配套实验：[`examples/05_learning_from_data/02_action_representation.py`](../examples/05_learning_from_data/02_action_representation.py)

## 1. 为什么这一篇是收口

前面八篇讲了怎么采、怎么存、怎么对齐、怎么验收。这一篇讲一个决定，它同时影响这三件事：

**动作用什么形式表示。**

它看起来是模型侧的选择——"我用回归还是用离散 token"。但只要你在做数据平台，就会立刻发现不是：

| 你的选择 | 对数据侧的连带后果 |
|---|---|
| 离散 token | bin 的定义（范围、数量、是否逐维）成为 schema 的一部分；换了 bin 定义的数据集**不能混训** |
| 连续回归 | 归一化统计量必须随版本存；否则同一个物理动作在不同版本里是不同数字 |
| 加 chunk | 数据形状从 `(T, D)` 变成 `(T, k, D)`；评估协议里必须写 chunk，否则成功率不可比 |
| 量化 | 量化步长决定安全余量下限；限位值不存量化的数据集，事后无法判断动作安全不安全 |

这一篇的四个实验，都在算同一件事：**一个表示选择，把多少成本推到了数据侧，推到了哪个环节。**

## 2. 三种表示的假设

先把它们各自"相信什么"摊开：

| 表示 | 隐含假设 | 什么时候成立 | 什么时候必然失效 |
|---|---|---|---|
| **连续回归（MSE）** | 给定状态下，动作服从单峰分布 | 精细操作、单一策略、短程 | 同一状态有多种正确动作（绕左 / 绕右） |
| **离散 token** | 动作可以量化到有限档位，且序列可自回归生成 | 动作本身离散（开/关、抓/放）或与 LLM 同构 | 需要亚毫米精度，或控制频率高 |
| **flow / diffusion** | 动作服从任意分布，可从噪声迭代去噪得到 | 多模态、高精度、连续 | 推理预算紧（要迭代多步） |

上一篇已经量过第一种的失效：双峰分布下 MSE 的预测值必然落在两峰之间，**100% 落在禁区**。这里不再重复，只算另外三种成本。

## 3. 量化误差：Δ/√12 就是你的预算公式

均匀分箱的误差有闭式解：真实值在 bin 内均匀分布时，量化误差的 RMSE 是

```
RMSE = Δ / sqrt(12)          Δ = 动作范围 / bin 数
```

实验验证（20000 个双峰样本，范围 [−1, 1]）：

| bin 数 | Δ | 理论 Δ/√12 | 实测 RMSE | 有效位数 |
|---|---|---|---|---|
| 16 | 0.12500 | 0.03608 | 0.03608 | 4.0 bit |
| 64 | 0.03125 | 0.00902 | 0.00904 | 6.0 bit |
| 256 | 0.00781 | 0.00226 | 0.00227 | 8.0 bit |
| 1024 | 0.00195 | 0.00056 | 0.00057 | 10.0 bit |
| 4096 | 0.00049 | 0.00014 | 0.00014 | 12.0 bit |

理论和实测吻合到第三位。这意味着**不用训练就能估预算**：

- 想要 1 mm 的位置精度、动作范围 1 m → Δ ≤ 0.001 → **bin 数 ≥ 2000（11 bit）**
- 想要 0.1° 的关节精度、范围 ±180° → **bin 数 ≥ 3600（12 bit）**

注意这两个需求同时存在时，bin 数不是"取个 256 就行"。VLA 里常见的 256 bin（8 bit）对应的精度是：位置 0.4 cm、关节 1.4°。这个精度对抓取杯子可能够，对插销孔不够。

**这也是为什么"离散 token"和"高精度操作"天然冲突**——不是模型学不会，是表示本身把信息扔了。

## 4. 归一化：全局 min-max 吃掉小量纲的分辨率

真实机器人的动作向量是**量纲混合**的：6 个关节（rad，±3）+ 1 个夹爪（0~1）。

如果按最常见的方式做全局 min-max，再用 256 个 bin 量化：

| 维度 | 真实范围 | 全局 min-max 的 bin | 每维 min-max 的 bin | 损失 |
|---|---|---|---|---|
| j1..j6 | [−2.90, +2.90] rad | 256.0 | 256 | ×1.0 |
| gripper | [+0.00, +1.00] | **44.1** | 256 | **×5.8** |

夹爪只剩 44 个可用档位，分辨率 0.0227。抓 5 mm 的物体需要 0.005 的分辨率——**全局归一化给不了，差 4.5 倍**。

这不是极端假设：任何"把整条动作向量当一维数组归一化"的实现都会踩。而它造成的失败非常隐蔽——关节动得很准，夹爪"偶尔抓不住"。

### 4.1 一条脏数据就够了

再叠一层：如果某条 episode 里有个关节因为碰撞过冲到了 3.60：

```
全局范围 [-2.90, 3.60]，跨度 6.50（原 5.80）
夹爪可用档位 39 个（原 44 个），分辨率 0.0254
→ 夹爪分辨率退化了 +12%
```

一条脏数据，整个数据集的夹爪精度掉 12%，而且**没有任何报错**。

所以归一化统计量必须：
1. **逐维做**（不是全局）
2. **用分位数**（1% / 99%）而不是 min/max
3. **随数据集版本一起存**——因为它是"把物理量变成网络输入"的那个变换，换版本不换它，语义就断了

## 5. 离散 token：真正的墙是吞吐，不是精度

"每维每步一个 token"是最直白的离散化（RT-2 属于这一类）。它的问题不在这里，在预算：

设定 7 维动作、控制频率 30 Hz（每步 33.3 ms）：

```
需要吞吐 = 7 维 × 30 Hz = 210 token/s
单序列能给 = 1000 / 15 ms = 67 token/s
缺口 = 3.1 倍
```

关键洞察：**这个缺口和 chunk 长度无关**。

| 方案 | token 数 | 延迟 | 允许花的时间 | 结论 |
|---|---|---|---|---|
| 每维每步 1 token, chunk=1 | 7 | 0.10 s | 0.03 s | 差 3.2 倍 |
| 每维每步 1 token, chunk=10 | 70 | 1.05 s | 0.33 s | 差 3.2 倍 |
| 每维每步 1 token, chunk=50 | 350 | 5.25 s | 1.67 s | 差 3.2 倍 |
| FAST 式频域 tokenizer（10×） | 35 | 0.53 s | 0.17 s | 留 3.1 倍余量 |
| 连续回归 / flow 动作头 | — | ~30 ms | 刚好 | 1 次前向，与 chunk 无关 |

chunk 变大，单次解码变慢，但允许花的时间同比变长——比值恒定。所以"加大 chunk"救不了吞吐缺口，因为缺口是**每秒 token 数**，不是每次 token 数。

对解码速度的敏感性：

| ms/token | 缺口倍数 | 现实对应 |
|---|---|---|
| 5 | 1.1× | 小模型 / 高度优化的推理栈 |
| 15 | 3.1× | 7B 级模型单序列 |
| 50 | 10.5× | 未优化 / 大模型 / 高精度 |

缺口是线性的：模型慢一倍，缺口大一倍。这就是为什么 FAST 这类**动作 tokenizer** 会出现——它把动作序列压成频域系数再离散化，用 5~10× 的压缩率换可接受延迟。代价是多一个编解码器：它本身要训练、有重建误差、而且**又多了一个必须存进数据集的 schema 组件**。

> 这里有个诚实的边界：15 ms/token 是我给的假设值，不是实测。实际数字取决于模型大小、批大小、推理栈。但结论对数量级不敏感——只要单序列解码在 10 ms 量级，210 token/s 就是一道硬墙。

## 6. 量化步长 = 安全余量的下限

最后一个，也是最工程的一条。

场景：夹爪指令 ≥ 0.95 就压碎物体。真实值落在 [0.90, 0.95) 这段安全带里。分箱之后有多少被推到线以上？

| bin 数 | Δ | Δ/2 | 被推过线比例（最坏对齐） | （最好对齐） |
|---|---|---|---|---|
| 16 | 0.12500 | 0.06250 | **100.0%** | 0.0% |
| 64 | 0.03125 | 0.01562 | 31.5% | 0.0% |
| 256 | 0.00781 | 0.00391 | 7.5% | 0.0% |
| 1024 | 0.00195 | 0.00098 | 1.8% | 0.0% |
| 4096 | 0.00049 | 0.00024 | 0.4% | 0.0% |

单值的最大推过量有严格上界 **Δ/2**。但一个区间里沦陷多少，取决于两件事：Δ 相对安全带宽度多大，以及网格和限位对不对齐。

同一个真实值 0.945、同一个 n=16，只是网格起点平移：

| 网格起点 | 量化结果 | 结局 |
|---|---|---|
| −1.000 | 0.9375 | 安全 |
| −0.970 | 0.9675 | **压碎** |
| −0.940 | 0.9975 | **压碎** |
| −0.910 | 0.9025 | 安全 |

同一个策略、同一个动作，结局取决于网格对齐——而这件事事先不可知。

**所以只能按最坏情况留余量：安全阈值 − 指令上限 ≥ Δ/2。**

对 schema 的要求很直接：限位值、量化步长、分箱范围必须一起存。只存限位不存量化的数据集，事后没法判断"这个动作是安全的"。

## 7. 怎么选：三个问题

不用记表格，按顺序问三个问题就够：

```
同一个状态，专家有没有给出过明显不同的动作？
  ├─ 有（多模态）→ 不能用 MSE
  │    ├─ 控制频率 ≥ 20 Hz → flow / diffusion（连续、一次出整段）
  │    └─ 频率低、动作本身离散 → 离散 token（可以和 LLM 同构）
  └─ 没有（单峰）
       ├─ 需要精度 ≤ 1 cm / 1° → 连续回归，逐维标准化
       └─ 精度要求松、又要和语言模型共用主干 → 离散 token，注意 Δ 的预算
```

三个问题里，第一个是**数据侧能回答的**：统计同一个（或邻近）状态下的动作方差。这也是为什么数据平台应该存"示范方差"这类统计量——它直接决定下游能用什么表示。

## 8. schema 必须存什么

把这一篇的结论收敛成一张清单。做数据平台的人可以直接拿去对照：

| 字段 | 为什么必须存 | 不存的后果 |
|---|---|---|
| 动作空间语义（绝对关节 / delta / EEF） | 同一个数字在不同语义下物理含义不同 | 跨数据集混训等于喂噪声 |
| **逐维**归一化统计量（分位数优先） | 归一化是物理量→网络输入的唯一变换 | 换版本重训后动作漂移 |
| 量化 bin 定义（范围 / 数量 / 是否逐维） | 它决定精度的理论上限 | 数据无法被别的模型复用 |
| 物理限位 | 判断动作安全性的基准 | 无法做事后安全检查 |
| chunk 长度 | 决定评估时的反应延迟口径 | 成功率不可比 |
| 控制频率 | 决定 token 吞吐预算 | 无法判断实时性 |

前五项里，只有第一项是"常识上会记得存"的。剩下四项，仓库里绝大多数开源数据集都没有——这就是为什么跨数据集复用动作总是要写一堆适配代码。

## 9. 对数据平台的四条结论

1. **动作表示不是模型超参，是 schema。** 它决定了数据能不能被别人用、能不能换模型重训。
2. **精度预算是算出来的，不是调出来的。** Δ/√12 这一条公式，能把"多少 bin 够"从实验问题变成算术问题。
3. **归一化必须逐维 + 分位数 + 随版本存。** 全局 min-max 会让小量纲维度损失 5 倍以上分辨率，而且不报错。
4. **量化步长要为安全余量负责。** Δ/2 是硬下界；对齐是运气，不能算进设计。
