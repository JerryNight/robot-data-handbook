# 05 · 从数据学策略

> 前四章都在回答「数据对不对」，这一章开始回答「数据够不够」——而"够不够"只有在策略跑起来之后才有意义。

| # | 文章 | 一句话结论 |
|---|---|---|
| 1 | [模仿学习](imitation-learning.md) | 样本翻 12 倍，覆盖只涨 1.2 倍——因为重复走同一条路 |
| 2 | [动作表示](action-representation.md) | 动作用什么形式表示不是模型超参，是 schema |
| 3 | [评测](evaluation.md) | 证明提升 5 个百分点，要 2,200 次 rollout ≈ 110 小时 |

每篇都配一个零依赖的可运行实验，在 [`examples/05_learning_from_data/`](../examples/05_learning_from_data/)。

## 这一章和前面四章的关系

前面四章的所有检查，都是**数据内部**的自洽性：时间戳对不对、动作和状态对不对得齐、有没有重复。

这一章冒出的是新一类问题——**数据和部署分布之间的关系**。这类问题：

- 不能只看数据发现，必须拿策略跑一遍
- 不改变数据的形状，只改变数据的**含义**
- 出问题时表现为"泛化不行"，而不是报错

所以它天然是数据平台的活：只有平台同时看得见"采了什么"和"模型在哪里用"。

## 三个数字串起全章

| 数字 | 含义 | 出处 |
|---|---|---|
| 12× / 1.2× | 演示条数增长的倍数 / 覆盖格数增长的倍数 | [模仿学习](imitation-learning.md) |
| 44 / 256 | 全局 min-max 归一化后夹爪可用的 bin 数 | [动作表示](action-representation.md) |
| 2,188 | 验证 5 pt 提升所需的总 rollout 数 | [评测](evaluation.md) |

三个数字分别对应三个层面的浪费：**采了用不上**（覆盖没扩）、**存了用不了**（精度被归一化吃掉）、**改了测不出**（样本量不够）。

## 贯穿全章的一条线：数据侧的决策，在模型侧以症状出现

| 数据侧的决定 | 模型侧的症状 | 你会误判成 |
|---|---|---|
| 演示只从一个起点采 | 换个初始位姿就废 | "模型泛化能力差" |
| 全局 min-max 归一化 | 夹爪偶尔抓不住 | "夹爪控制有问题" |
| 动作量化到 8 bit | 插销孔永远差一点 | "精度不够，加数据" |
| 评测集混入训练场景 | 报告虚高 7 pt | "这个方法有效" |
| 测试集太小 | 两个方法"看不出区别" | "改进无效" |

每一行的正确诊断都不在模型侧。这是做数据平台最需要建立的一种直觉：**先怀疑数据的覆盖和口径，再怀疑模型**。

## 数据条件决定能用的方法

数据的形态决定了能用的方法，反过来也成立：

| 数据条件 | 适合的方法 | 对应文章 |
|---|---|---|
| 少量高质量演示（< 100 条/任务） | 行为克隆 / ACT | [模仿学习](imitation-learning.md) |
| 演示质量参差、有失败样本 | 加权 BC、筛选后训练 | [模仿学习](imitation-learning.md) |
| 同一个状态有多种正确做法 | flow / diffusion（不能用 MSE） | [动作表示](action-representation.md) |
| 有仿真环境 | RL + sim2real（成本可能更低） | — |
| 大规模多本体数据 | 预训练通用策略（VLA 路线） | 阶段 6 |

**新手的常见误判**：以为算法选对了就能好用。实际上绝大多数失败来自数据——动作空间定义不一致、控制频率对不上、覆盖不够广。

## 三个方法层面的选择，怎么定

```
同一个状态，专家有没有给出过明显不同的动作？
  ├─ 有（多模态）→ MSE 必然失效
  │    ├─ 控制频率 ≥ 20 Hz → flow / diffusion + chunk
  │    └─ 频率低、动作离散 → 离散 token（和 LLM 同构）
  └─ 没有（单峰）
       ├─ 动作抖、来回犹豫 → 检查是不是采样频率太高
       └─ 长程任务后半段崩 → 加 chunk / 分层
```

判断第一行的方法是**统计数据侧的方差**：同一（或邻近）状态下动作的分散程度。这是数据平台应该能直接给出的指标。

## 常见错误清单

- 用 episode 条数衡量数据规模，不看状态覆盖
- 认为「数据不够就多采」，忽略多模态是目标函数问题而非数据量问题
- 把 DAgger 当成万能药——它只修分布偏移，不修表达能力
- 全局 min-max 归一化动作向量（量纲混合时小量纲维度损失 5 倍以上分辨率）
- 归一化统计量不随数据集版本存
- 离散 token 只算精度不算吞吐（7 维 × 30 Hz = 210 token/s 是硬墙）
- 量化步长不和物理限位一起校验（安全余量必须 ≥ Δ/2）
- 用 20 次试验的 75% 成功率下结论（区间宽度 36 pt）
- 报成功率不写测试分布（同一批模型，差距能从 4 pt 变 41 pt）
- 按 episode ID 而不是场景 ID 划分训练/评测集
